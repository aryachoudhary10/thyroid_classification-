# Paper figures — ConvNeXt-Tiny (primary) + ResNet-50 (supplementary)

Every number in every figure here is read from a real result file under
`../kaggle_jobs/**` (produced by actual training/evaluation runs on Kaggle) or
computed live from real model instantiations / checkpoints on this machine.
Nothing is estimated, interpolated, or invented.

## Structure

```
paper_figures/
  fig01_dataset.py, fig02_performance.py, fig03_ablation.py,
  fig04_mechanism.py, fig05_calibration.py, fig06_robustness.py,
  fig07_significance.py, fig08_external.py, fig09_computational.py,
  fig10_architecture.py, fig11_error_analysis.py
  output/                          <- ConvNeXt-Tiny results (primary, 11 figures)
  make_all.py                      <- rebuilds everything above

  resnet50_supplementary/
    fig02_performance_resnet50.py, fig04_reliability_mechanism_resnet50.py,
    fig05_calibration_resnet50.py, fig06_robustness_resnet50.py,
    fig07_significance_resnet50.py, fig08_external_resnet50.py,
    fig09_computational_resnet50.py, fig11_error_analysis_resnet50.py
    output/                        <- ResNet-50 + RCAF results (supplementary, 8 figures)
    make_all.py                    <- rebuilds the supplementary set
```

**Framing for the paper: "here is what we did" is the top-level (ConvNeXt-
Tiny) set — all 11 figures. "We also tried ResNet-50 and here is what we got,
including the published RCAF baseline" is `resnet50_supplementary/`, reported
separately.** No figure in either set mixes backbones.

## Reproduce

```bash
cd paper_figures && python make_all.py                        # primary (ConvNeXt-Tiny), 11 figures
cd resnet50_supplementary && python make_all.py                # supplementary (ResNet-50 + RCAF), 8 figures
```

Each figure produces `output/png/*.png` (300 dpi), `output/pdf/*.pdf` and
`output/svg/*.svg` (vector), and `output/captions/*.txt` — the caption text is
generated by the same script that made the figure, with numbers computed
inline, not typed by hand.

## The reliability-mechanism and robustness gap (closed)

The mechanism-analysis (Fig. 4) and robustness suite (Fig. 6) were originally
only ever computed on ResNet-50, because `der_mil`'s ConvNeXt-Tiny checkpoint
and `lesion_mil`/`mr_mil`'s ConvNeXt-Tiny checkpoints came from **two
separate, never-chained Kaggle kernel lineages** (`dermil-convnext`, trained
`der_mil` alone, vs `dermil-convnext-ablation`, trained the other two) — they
were only ever merged locally on disk, not on Kaggle. A first attempt to close
this gap chained from only one of the two lineages, which silently excluded
`der_mil` from the analysis; a corrected run chained from **both** sources and
merged their `registry.json` files by key before running. All 11 primary
figures are now genuinely ConvNeXt-Tiny.

Two findings from this that do **not** replicate the ResNet-50 pattern, and
are reported as such rather than smoothed over:

- **Which region misbehaves is backbone-dependent.** On ResNet-50, `core`
  showed the inverted (wrong-sign) reliability-influence correlation and
  `margin`/`peri` showed the correct sign. On ConvNeXt-Tiny, `core` shows the
  *correct* sign and `peri` inverts instead; `global`'s reliability is so
  uniform across every single test patient's frames that no correlation
  could even be computed for it (a more extreme version of the same
  near-constant pattern seen on ResNet-50). If the mechanism captured a
  stable anatomical signal, the same region would misbehave on both
  backbones — it does not (Fig. 4).
- **The frame-removal robustness direction reverses.** On ResNet-50,
  removing DER-MIL's own lowest-reliability frame hurt ranking performance
  least (the informative direction). On ConvNeXt-Tiny it hurts *most* — the
  wrong direction (Fig. 6).
- **The DER-MIL-over-MR-MIL TN5000 external advantage does not replicate.**
  On ResNet-50, DER-MIL significantly beat MR-MIL on both TN5000 mask arms
  (p=0.044, p=0.031). On ConvNeXt-Tiny the two are statistically
  indistinguishable (p=0.53) and MR-MIL nominally leads (Fig. 8).

## What is not built anywhere (neither set)

No raw ThyroidXL/TN5000 pixel data, saved attention weights, or model
embeddings exist in this local environment — every training and evaluation
run happened on Kaggle, and only result tables and a handful of checkpoints
were ever fetched back. So, in both the primary and supplementary sets:

- Representative ultrasound images / preprocessing / ROI crops
- Attention-MIL visualisation overlaid on actual frames
- Grad-CAM for correct/incorrect predictions
- Feature-space t-SNE / UMAP / PCA of patient or frame embeddings

are not producible from what exists locally, and are not faked with
placeholders. Fig. 4(d) is the closest real substitute: the model's own
per-frame reliability score for one real test patient, plotted from the raw
per-token dump — a genuine per-frame signal, not an image overlay.

Unlocking the four items above needs one additional Kaggle inference pass
that saves small artefacts (rendered Grad-CAM PNGs, attention alphas,
embedding vectors, a handful of representative crops) — a scoped CPU/GPU job,
not a retraining run — which has not been launched.
